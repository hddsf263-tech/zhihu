> 版本：v1.0  
> 日期：2026-09-13  
> 产品负责人：成员一  
> 状态：依据已确认产品方向编写的需求基线，待团队评审；不代表功能已实现或通过验收。  
> 依据：《知乎经验地图｜产品与工程执行规范》v1.0.0（PROJECT_SPEC(1).md），以及成员一对目标用户、痛点和多路线方案的确认。

## 1. 产品概述

### 1.1 名称、口号与定位

- **产品名称：** 知乎经验地图。
- **产品口号：** 把零散经验，变成看得懂、能比较、有出处的下一步。
- **产品定位：** 基于可获取的知乎公开内容摘要，结合用户条件，整理多条有来源依据的参考路线，并将用户选择的路线转化为行动清单的独立响应式 Web 工具。

### 1.2 目标用户

在知乎提出决策型问题，收到多个回答后，仍难以结合自身条件分析利弊、做出选择并采取行动的人。

首版聚焦正在寻找第一份产品经理实习、准备经验不足的在校大学生。提出问题是典型使用背景，不是访问门槛：用户也可以输入主题，或粘贴已有的知乎问题链接。v1 不要求登录知乎，不验证提问者身份，也不自动读取用户账号下的问题。

### 1.3 核心痛点

回答中的建议较为零散，适用条件各异，甚至相互冲突。用户难以比较不同方案的收益、成本和风险，也缺少具体的实施步骤，导致看了很多回答，仍不知道如何开始。

这一痛点是当前产品假设，尚无本项目用户访谈结果支撑。后续应通过目标用户访谈和原型试用验证，不能将其描述为已验证的普遍事实。

### 1.4 最终产出

基于可获取的知乎内容摘要，结合用户提供的目标和条件，整理出 1–3 条有来源支撑的参考路线，展示各自的适用条件、利弊、风险和阶段任务。用户比较并选择一条后，获得可勾选、可导出的行动清单。

路线数量由证据决定：证据足够时通常呈现 2–3 条；只支持一条时仅展示一条；不满足证据门槛时展示已有来源及缺失说明，不生成无依据的路线。系统帮助用户理解取舍，不宣称某条路线是唯一正确或最优答案。

## 2. 产品目标与首版边界

### 2.1 用户应能够完成的事情

1. 看懂不同路线在策略、适用条件和投入上的主要差异。
2. 判断哪些路线更符合自己的背景、时间和预算，并理解尚未确认的信息。
3. 找到关键行动的来源依据，回到知乎核对原文。
4. 自主选择路线，明确下一步任务及完成判据。
5. 保存任务完成状态，并导出包含来源的清单。

### 2.2 首版范围

| 优先级 | 功能 | 用户可见结果 |
|---|---|---|
| P0 | 主题或知乎问题链接输入 | 通过两种入口发起整理 |
| P0 | 可选用户条件 | 补充背景、准备周期、每周时间和预算 |
| P0 | 知乎内容获取与来源整理 | 看到可追溯的摘要、内容类型和原文链接 |
| P0 | 有条件路线生成 | 获得证据支持的路线、阶段任务、适用条件与风险 |
| P0 | 路线比较 | 在相同维度下理解不同方案的取舍 |
| P0 | 引用抽屉 | 查看行动对应的证据和来源 |
| P0 | 行动清单 | 选择路线后勾选、本机保存并导出 Markdown |
| P0 | 异常与演示回放 | 能识别失败、证据不足、缓存和人工核验的演示案例 |
| P0 | 响应式与基本无障碍 | 在电脑、手机及键盘操作下完成主流程 |
| P1 | OAuth、个人收藏、热榜、问题推荐、故事或知识能力 | P0 验收后按实际增益评估，不作为首版前置条件 |

v1 不做真人聊天或匹配、代发内容、自动邀请回答、任意网页或全文抓取、账号画像推断、复杂节点画布、移动原生 App、云端保存、分享和自由追问。清单仅保存在本机，不称为“同步知乎收藏”。不承诺医疗、投资等高风险主题的决策质量。

## 3. 主场景与使用故事

### 3.1 固定主场景

| 项目 | 内容 |
|---|---|
| 用户 | 准备寻找第一份产品经理实习的在校大学生 |
| 问题 | 大学生如何准备第一份产品经理实习？ |
| 背景 | 零实习经历 |
| 准备周期 | 8 周 |
| 每周可投入时间 | 10 小时 |
| 预算 | 500 元 |
| 决策困境 | 看到先做作品集、尽早投递、参与校园项目等建议，不知道如何比较和安排 |
| 期望结果 | 看懂可选路径，选择符合自身条件的一条，开始执行第一项任务 |

以上为演示场景设定，不是已访谈用户的真实经历。“先做作品集”“边做边投递”“通过校园项目积累”只是候选方向，必须由真实来源支持；证据不支持时减少或调整路线，不硬套三个名称。

### 3.2 使用故事

一名零实习经历的大学生阅读了多个知乎回答，仍不确定该先做作品集、参与项目还是开始投递。他打开经验地图，输入问题，补充 8 周、每周 10 小时和 500 元预算。

系统检索可用摘要并整理证据，呈现有依据的参考路线。用户比较各路线的核心策略、准备周期、投入、预算和适用前提，展开阶段任务，并通过引用查看具体建议的出处。用户依据自己的情况选择一条路线，进入行动清单，完成并勾选第一项任务，之后可以继续使用当前浏览器查看进度或导出 Markdown。

### 3.3 备用验证场景

问题：**独立开发者应该先做产品，还是先做内容？**

用于检验输入、证据整理、路线比较和清单机制是否依赖主场景硬编码。备用问题不预设结论；未输入的条件保持未指定。主、备用场景各准备一套人工核验的回放案例。

## 4. 输入、输出与内容结构

### 4.1 用户输入

| 输入项 | 规则 | 产品说明 |
|---|---|---|
| 输入模式 | 主题 / 知乎问题链接 | 默认主题模式，可主动切换 |
| 主题 | 主题模式必填 | 使用自然语言描述需要解决的问题 |
| 问题链接 | 链接模式必填 | 仅接受规范规定的知乎问题 URL，不导入任意网页 |
| 重点关注什么 | 链接模式选填 | 帮助明确整理关注点，不等同于自由追问 |
| 背景 | 选填 | 如“零实习经历” |
| 准备周数 | 选填 | 不填表示未指定 |
| 每周小时数 | 选填 | 不填表示未指定 |
| 预算（人民币） | 选填 | 0 元是有效条件，与未填写不同 |

具体长度和数字范围由成员二在共享 contracts 中统一定义并供前端使用，实施前与成员一确认；本 PRD 不另设相互冲突的限制。条件用于整理与解释路线，不声称知乎搜索支持按这些条件筛选，也不保证检索结果完全符合用户条件。

### 4.2 结果结构

| 内容 | 必须表达的信息 |
|---|---|
| 问题与条件 | 本次整理的问题、已填写条件及未指定项 |
| 数据状态 | 实时整理、缓存结果或演示案例；生成时间与来源获取时间 |
| 概览 | 问题中的关键选择和需要关注的取舍 |
| 参考路线 | 名称、核心策略、适用条件、比较维度、风险和引用 |
| 路线阶段 | 每条路线 2–5 个阶段，每阶段 1–3 个任务，任务有完成判据 |
| 观点差异 | 有证据支持的策略或前提差异；无依据时不制造分歧 |
| 来源与证据 | 摘要、引用片段、内容类型、可用元数据和官方原文链接 |
| 局限说明 | 摘要覆盖范围、未知信息及需要用户核对的内容 |
| 行动清单 | 复用所选路线任务，保留来源、状态和建议安排 |

比较统一围绕准备周期、每周投入、预算、适用前提展开。来源未提供具体数值时显示“资料未说明”或明确标记产品建议，不为补齐卡片而编造数字。预期收益以有依据的文字说明，不给出无来源的成功率或结果承诺。

## 5. 用户流程与页面需求

主流程：**输入问题和条件 → 创建整理任务 → 查看路线与比较 → 核对来源 → 选择路线 → 勾选、保存和导出清单。**

### 5.1 首页 `/`

**目的：** 让用户理解产品价值，并以较低成本发起一次整理。

必须展示名称、口号、简短价值说明、两种输入模式、可折叠条件区，以及两个有明确区别的示例入口。

- “填入实习示例”：仅填入固定主场景问题与条件，不自动提交。
- “生成经验地图”：校验通过后提交；立即禁用重复点击，进入整理页。
- “查看已整理案例”：进入明确标记的回放流程，不调用知乎或模型。
- 在主题框直接粘贴问题 URL 时，提示切换模式，不静默改变输入含义。
- 网络重试遵循原契约的幂等规则，避免重复创建相同任务。
- 校验失败就地说明原因，保留用户输入；不展示假登录、假人数和不可用按钮。

**验收：** 主题与链接两种入口均能提交；条件空值和预算 0 正确区分；示例填入不触发任务；重复点击不会产生多个上游任务。

### 5.2 整理页 `/jobs/:jobId`

**目的：** 让用户知道当前进度，并在异常时有清晰出路。

阶段文案固定为：排队中 → 查找知乎内容 → 整理经验路线 → 检查来源。显示问题和条件上下文，不展示编造百分比、虚构阅读数量或模型内部推理。

- 每 1500ms 查询本应用任务状态；刷新后可凭 jobId 恢复查询。
- 成功后进入地图；失败展示可理解的原因并保留输入。
- 仅服务端明确允许重试时提供重试操作。
- 返回修改只停止浏览器等待，不声称取消服务端任务。
- 离开页面清理轮询；95 秒未到终态时提示连接中断并停止自动轮询，不将其描述为已确认的服务端失败。
- 未知状态不判定为成功。

**验收：** 四阶段文案准确；刷新可恢复；成功、失败、过期和等待中断有明确表现；离开后不继续轮询。

### 5.3 地图页 `/maps/:mapId`

**目的：** 帮助用户理解不同路线的取舍并自主选择。

展示顺序固定为：问题与条件 → 数据状态 → 概览 → 路线卡片 → 当前路线阶段 → 有证据的观点差异 → 来源 → 行动清单入口。

- 默认展开第一条路线，但不标为“最优”或“最适合”。
- 多条路线使用同一组维度比较；切换与比较不发起额外模型请求。
- 只有一条路线时隐藏比较开关，仍展示适用条件、风险和证据。
- 无合格路线时展示已有来源和缺失说明，不展示可选择的空路线或虚构清单。
- 阶段展示任务、完成判据和引用；“第几周”明确标为建议安排。
- 用户点击引用编号打开来源抽屉。
- 用户选择路线后进入对应清单，复用已有任务，不再次调用 AI。

**验收：** 能说明路线之间的实质差异；选择与清单对应正确；引用均能定位；1 条、多条、证据不足三种情况均可理解。

### 5.4 来源抽屉

**目的：** 让用户知道关键行动来自哪里，以及来源实际说了什么。

桌面使用右侧抽屉，手机使用全屏弹层。展示内容类型、可用标题、作者信息（若有）、接口返回摘要、引用片段、获取时间与“查看知乎原文”。

- 缺失作者时隐藏该项或显示“作者信息未返回”，不猜测。
- 缺失标题时可用“该问题下的回答摘要”作为界面标签，不冒充原文标题。
- 引用必须是对应规范化摘要中的连续片段，并保留上下文供核对。
- 官方原文链接保留返回的 UTM，新标签打开，使用安全外链属性。
- 支持键盘进入、Esc 关闭、弹层内焦点限制及关闭后焦点恢复。

**验收：** 用户能从任务定位到证据和来源，再跳转官方原文；作者缺失、长摘要和键盘操作均正常。

### 5.5 行动清单页 `/maps/:mapId/plan?routeId=...`

**目的：** 将已选择的路线变成可以持续执行的任务。

- 展示所选路线、输入条件、分阶段任务、完成判据、引用与勾选状态。
- 任务来自已有地图，不重新生成或随意改写。
- 勾选后在当前浏览器本机保存，刷新可以恢复；清晰说明不跨设备同步。
- 不同地图、不同路线的完成状态互不覆盖。
- 支持导出 `.md`，包含输入条件、任务状态、来源链接、生成时间及实时/缓存/回放说明。
- 返回地图后可重新比较和选择其他路线。

**验收：** 勾选、取消勾选、刷新恢复、路线状态隔离和导出均工作；导出内容与页面一致。

## 6. 内容可信度与评价标准

以下为 PRD 级验收底线，详细人工审核表由 `content-rubric.md` 和 `case-review.md` 承接。

| 维度 | 合格标准 |
|---|---|
| 来源真实 | 仅使用可获取的官方接口摘要与真实返回元数据；直答不是原始证据来源 |
| 引用准确 | sourceId 存在；quote 为对应规范化摘要中的连续片段；人工确认未断章取义 |
| 支撑充分 | 每条路线至少引用两条不同内容；核心行动有直接证据支撑 |
| 路线有差异 | 差异体现在策略、投入顺序或适用前提，不只是更换标题 |
| 条件可解释 | 说明与用户条件的关系；资料不足时标记待确认，不假装完全匹配 |
| 建议可执行 | 有明确动作和完成判据，避免只有“多学习”“提升能力”等泛泛表达 |
| 信息有区分 | 证据摘要、AI 整理或建议、资料未说明清晰区分；具体标签实现遵循现有契约 |
| 不夸大 | 不把摘要称为全文，不编造作者、预算、用时或成功率，不承诺求职结果 |

成员一逐条审核主、备用案例中的核心行动、来源、引用与路线差异。审核不通过的结果只能用于明确标注的开发演示，不作为已核验案例。

## 7. 异常、缓存与演示回放

| 情况 | 页面应表达什么 | 用户可以做什么 |
|---|---|---|
| 输入不合法 | 指明需要修改的字段 | 修改后提交 |
| 未检索到内容 | 本次未找到可用摘要，不伪装成生成成功 | 修改问题，或查看演示案例 |
| 证据不足 | 展示可用来源（若有）和缺失说明 | 调整问题或条件 |
| 上游超时或失败 | 说明内容服务暂不可用 | 按 retryable 决定是否提供重试；可进入回放 |
| 达到调用限制 | 明确说明达到调用限制 | 稍后尝试或查看演示案例，不自动循环重试 |
| 结果校验不通过 | 说明暂未得到可靠路线 | 按服务端指示处理，不渲染非法结果 |
| 任务过期 | 说明任务已过期 | 返回保留的输入，重新发起整理 |
| 本机保存失败 | 明确提示当前进度未保存 | 保持当前页面可操作，并允许导出清单 |

数据状态必须可见：

- **实时整理：** 本次调用知乎获取内容。
- **缓存结果：** 使用已有历史快照，显示对应时间，不声称为本次检索。
- **演示案例：** 使用人工核验的预置结果，明确不是实时请求。
- **合成测试数据：** Mock 的固定标记，不冒充真实案例。

现场准备主、备用两套回放。回放不得调用知乎或模型；断网回放必须在约定的本地或预载演示环境中完整实测，不能仅因“使用缓存”就宣称已经支持断网。

## 8. 视觉、可用性与隐私要求

- 沿用技术规范：主色 `#1769E0`、背景 `#F6F7F9`、正文 `#172033`。
- 桌面宽度 ≥1024px 时主区最大 1200px；手机 <768px 时顺序阅读，引用全屏显示。
- 必测 360、390、768、1440px，无整页横向溢出。
- 手机正文至少 16px，说明至少 12px，点击区域至少 44×44px。
- 状态不只依赖颜色；关键流程可用 Tab、Enter、Esc 完成；加载与错误可被辅助技术理解。
- 不在产品中展示工程错误堆栈、密钥、内部请求细节或模型推理。
- 知乎或模型凭证仅在服务端；前端不直连这些服务。
- 本机清单仅存储必要路线与任务状态，不存凭证或账号数据；提示用户避免在背景栏填写不必要的敏感信息。

## 9. 技术协作边界

本 PRD 描述用户行为和验收结果，不另设技术栈或数据字段。继续沿用技术规范中的 pnpm workspace、React、Express、Zod contracts、SQLite 和单容器同源部署方案。

前后端继续使用以下已有契约，不采用早期讨论中的单一同步接口 `POST /api/experience-map`：

| 接口 | 产品用途 |
|---|---|
| `POST /api/v1/maps/jobs` | 发起实时或回放整理任务 |
| `GET /api/v1/maps/jobs/:jobId` | 查询处理状态 |
| `GET /api/v1/maps/:mapId` | 获取不可变地图快照 |

`ExperienceMap`、错误码、幂等规则和本机清单存储格式以技术规范及 `packages/contracts` 为准。成员三使用共享 contracts 和 fixtures；成员二提供有效结果、无路线及异常样例。

若实现本 PRD 需要新增字段、改变接口或调整 P0，先记录 ADR 并由成员二与受影响成员确认。当前工作目录存在的代码不作为功能完成或已符合技术规范的证明；本次仅新增产品文档，不调整工程。
